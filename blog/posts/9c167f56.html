加密社交 App 流量分析（一）：从论文提炼分类依据

2026-11-16 · tech / 流量分析 · 约 3546 字 · 阅读约 9 分钟

加密社交 App 流量分析（四篇）：一·分类依据 ｜ 二·数据与实验 ｜ 三·规则提炼 ｜ 四·总结

源文件：3658644.3670375.pdf 标题：Rules Refine the Riddle: Global Explanation for Deep Learning-Based Anomaly Detection in Security Applications 作者：Dongqi Han, Zhiliang Wang, Ruitao Feng 等（清华大学 / 中关村实验室 / SMU / NTU） 出处：ACM CCS ‘24, Salt Lake City, UT, USA，15 页 DOI：10.1145/3658644.3670375

0. 一句话定位

这篇论文本身不是一篇”移动社交 App 流量分类”论文，而是面向安全领域深度学习异常检测的全局解释（XAI）方法——GEAD。 但它的两个落地场景之一是网络入侵检测（NIDS），因此论文正文与附录里完整给出了：

  1. 网络流量如何被表示（三种粒度）；
  2. 网络流量依据哪些特征被分类（四类特征依据）；
  3. 深度学习模型用什么范式判定（两类检测范式 + 阈值）；
  4. 如何从黑盒模型里把判定依据反向提炼成规则（GEAD 六步）；
  5. 规则如何被评价（保真度 / 简洁度 / OOD 评估）。

这正是本任务要的”分类依据 + 方法 + 规则提炼”的骨架。

1. 流量的三种表示粒度（论文用三个数据集对应）

数据集粒度特征来源论文中出现的代表特征
Kitsune（Mirsky et al., NDSS’18）包级 / 包统计在 IoT 网络里打多种攻击，从流量中抽取包级统计量包级统计特征（论文 §4.1）
CICIDS2017（Sharafaldin et al.）流级（flow-level）模拟企业网中正常行为 + 常见攻击，切成双向流后抽特征Bwd_Pkt_Len_Min、Bwd_Head_Len、Pkt_Len_Var、Pkt_Len_Std、Init_Win_Bytes_Fwd/Bwd、Bwd_Seg_Size_Avg、Bwd_IAT_Std、Active_std、#SYN/#URG/#FIN
Kyoto2006+（Song et al.）会话级（session-level）京都大学网络里蜜罐 2006–2015 的日常流量Service_dns、Srv_serror_rate、Dst_host_serror_rate、Protocol_udp
（附加） HDFS序列级（日志 key 序列）Hadoop 文件系统日志序列日志 key、事件信息分箱

对本任务的直接启示：本项目数据是 NFStream 输出的双向流级特征，正好落在 CICIDS2017 这一档 （流统计 + 包长统计 + 时延统计 + 标志位 + TLS/QUIC 元数据），并且额外提供了”按会话/按天聚合”的空间， 可以复现论文 README 里提到的 multi-flow aggregation（多流聚合）。

2. 流量分类的”特征依据”：论文归纳出的四类

从论文 §4.3 给出的 DDoS 规则、以及附录 C 的规则树可以直接反推出它使用的特征依据分四族：

依据族含义论文原文特征（CICIDS17 / Kyoto）判别力来源
① 体量与包长统计一次会话搬了多少字节、包长分布形状Bwd_Pkt_Len_Min、Pkt_Len_Var、Pkt_Len_Std、Bwd_Seg_Size_Avg、Bwd_Head_Len、Init_Win_Bytes_*应用/协议的内容形态（文本小包 vs 视频大包 vs 错误页大包）
② 时间与到达间隔统计节奏、突发、静默Bwd_IAT_Std、Active_std交互式（聊天）vs 流式（视频）vs 轮询（心跳）的时间结构
③ 传输层协议与标志位TCP/UDP/QUIC 选择、标志位计数Protocol_udp、#SYN,#URG,#FIN协议栈与连接建立方式（长连接 / 短连接 / 无连接）
④ 服务/端口/主机行为速率服务类型与统计速率Service_dns、Srv_serror_rate、Dst_host_serror_rate目标服务画像与错误率

论文对 ③ 有一个重要的方法论警告：CICIDS2017 里 TCP 标志位特征提取有 bug（只统计了每条流的第一包），导致”#SYN,#URG,#FIN = 0” 这种反常识特征被误当作关键依据；改正后 ROC-AUC 从 0.75 → 0.90，DDoS 召回 25.3% → >99.9%。 → 启示：特征提取实现本身可能制造伪规则，必须回到原始流量核验。

3. 论文的”分类方法”：两类检测范式 + 阈值判定

论文 §2.1 把 DL-based 异常检测分为两类，二者都是 zero-positive learning（只用正常样本训练）：

3.1 重构式（Reconstruction-based）

  • 模型：AutoEncoder（AE）、GAN
  • 训练目标：最小化正常输入与重构输出之差（MSE）
  • 判定：重构误差 > 阈值 → 异常；误差即”异常分”
  • 代表：KitNET（两层 AE 集成，从网络包抽统计特征）

3.2 预测式（Prediction-based）

  • 模型：RNN / LSTM
  • 训练目标：用前 n 个时间点预测下一个时间点
  • 判定：下一时间点的预测概率低 → 异常
  • 代表：DeepLog（把日志条目映射成 log key，再对 key 序列做 LSTM 预测）

3.3 关键共性

检测器的输出是连续的异常分（anomaly score），二值化只发生在最后一步阈值比较。 → 这正是 GEAD 选择”回归树拟合连续分数”而不是”分类树拟合 0/1”的原因（下一节）。

论文明确说明：有监督分类不是本文主线，决策树只作为”可解释替代模型”（explainable model）出现。

4. 核心方法：GEAD 六步（规则提炼的骨架）

GEAD = Global Explanation for DL-based Anomaly Detection。目标是：把黑盒 DL 检测器的决策逻辑，蒸馏成一棵可读的规则树。

①回归树生成 → ②低置信叶识别 → ③低置信增广 → ④子树生成 → ⑤树合并+离散化 → ⑥可读规则生成

① 回归树生成（Regression Tree Generation）→ root tree

  • 输入：与原检测器完全相同的训练集 X
  • 标签：原检测器在 X 上的输出分数 F(X)（不是 0/1 标签）
  • 算法：CART 回归树，分裂准则 MSE（最小化区间内目标方差）
  • 产出：root tree
  • 为什么用回归不用分类：分类树只学到”正常/异常”的二元结果，丢掉”异常程度与分布”；回归树能把分数梯度带进规则，保真度更高。

② 低置信叶识别（LC Leaves Identification）

两类 LC 空间，用两个分位数阈值 α_O、α_E（默认 0.99）同时选：

  • 原模型的 LC：叶内样本的异常分高于 α_O 分位 → 该区域本来就在训练分布之外，模型自己就不确定
  • 解释树的 LC：叶子的不纯度高于 α_E 分位 → root tree 没拟合好 → 合并两类，得到需要细化的 LC 叶集合。

③ 低置信增广（LC Augmentation）

在每个 LC 叶的特征子空间内，用原模型梯度”逼”出不一致样本：

  • 约束：决策路径上已出现的特征（阈值条件）固定不动，只扰动其余特征 → 保证不破坏上层规则
  • 双向生成：
    • 负方向 X⁻：沿降 MSE 方向走 X_j = X_{j-1} − β·∂MSE/∂X
    • 正方向 X⁺：反向爬升，并加 ReLU(σ − MSE) 上限（σ 经验取 2×阈值），防止 loss 爆炸
  • 迭代 N 次（默认 20），步长 β（默认 0.1）；论文附录 B.1 证明 β∈[0.01,1]、N∈[5,50] 内结果不敏感

④ 子树生成（Subtree Generation）

把该 LC 叶的所有增广样本再拟合一棵回归树（同 ① 的做法）→ 得到细粒度 subtree。

⑤ 树合并 + 离散化（Tree Merging & Discretization）

  • 因为增广时没动决策路径特征，所以可以直接用子树替换对应 LC 叶 → merged tree
  • 再按原检测器阈值把叶子数值二值化（正常/异常），或分成多档”异常程度”；自底向上把同档相邻叶合并，压缩规则数

⑥ 可读规则生成（Human-readable Rule Generation）

  • 每片叶子 → 一条规则 = 从根到叶的路径
  • 规则元素是三元组：(特征, 决策阈值, 关系)
  • 连续特征可再离散成 small / large，提升可读性
  • 规则按异常程度排序输出
  • 论文给出的真实 DDoS 规则示例（KitNET on CICIDS17，方块内自上而下 = 从根到叶）：
Context (Common)        (1) Init_Win_Bytes_Fwd ≠ −1 ∩ ∈ (0, 50000)
                        (2) # SYN, URG, FIN = 0
                        (3) Init_Win_Bytes_Bwd ∈ (2, 40000)
                        (4) Pkt_Len_Var > 1E7
                        (5) Active_std < 40000

True Positive  分支      (3) Init_Win_Bytes_Bwd = −1
                        (4) Pkt_Len_Var < 8E6
                        (5) Bwd_IAT_Std < 4E7        → False Negative

补充机制

  • 预剪枝：用最大深度 M_d + 叶最小样本数 M_s 控制规则数（不用 CCP/top-k 后剪枝，因为后剪枝对评估样本敏感且无法控制规则总数）
  • 时序扩展：把窗口展平成表格维度（窗口 5 → 5 维特征），并强制所有时间点在规则里出现以保留上下文

5. 论文的”规则质量”评价指标

指标定义说明
Positive Consistency原模型判正的样本中，解释树也判正的比例从原模型视角看”漏了多少”
Negative Credibility解释树判负的样本中，原模型也判负的比例从解释树视角看”谎报了多少”
Fidelity（保真度）两模型决策一致程度必须用 IID + OOD 混合评估，否则会得到假保真（论文 Fig.1 玩具例子：IID 下保真度 100%，OOD 下 0%）
Conciseness（简洁度）规则（分支）条数与保真度存在 trade-off，需设定规则预算
其它stability / efficiency / robustness论文 §6 讨论；GEAD 单次运行 3s（CICIDS17），Trustee 2407s，KITree 3170s

基线：DT(IID+OOD)、DT(Trustee)、RT(IID)、RT(Trustee)、KITree。 结论（Table 1）：RT(GEAD) 在四个数据集上一致性/可信度全面最优（如 CICIDS17：正一致性 0.923 vs RT(IID) 0.882、DT 0.509）。

6. 论文的 5 条洞察（对”提炼规则”最有价值的结论）

  1. Insight 1：DT 解释无法正确反映 DL 异常检测的决策逻辑；只用 IID 的回归树也会忽略/歪曲部分逻辑。
  2. Insight 2：DL 异常检测很少”捷径学习”——不可能用少数几条规则描述完（对比监督模型 10 条规则即可 99% 保真）。原因：学习目标是回归式分数。
  3. Insight 3：模型规则常与常识冲突，因此”离群 ≠ 恶意”的判断要谨慎。冲突三大来源：特征提取不准 / 标签错误 / 模型训练不当。
  4. Insight 4（规则重要性方向相反）：
    • 对整个模型：越靠近根的规则越重要；
    • 对某一条具体决策：越靠近叶的规则越重要（直接决定该叶划分）。
  5. Insight 5：不同设置下训练出的模型，规则条数常与检测性能成反比 → 可用”最少规则”作为选 epoch / 选训练集大小的代理指标（论文 Table 2：命中全局最优 59%，远超早停的 1%）。

三种用法：

  • Model vs Expert：模型知识 vs 领域常识 → 完美模型 / 模型超越专家（有价值）/ 模型学错（查特征/标签/模型）
  • Model vs Model：不同训练数据、超参、训练技巧下对比规则 → 用于选型、验证重训/遗忘
  • Model + Expert：规则融合（论文 SCADA 落地：专家规则 FP/FN 很高，融合后 Device1 FP 19,786→94、FN 821→217）

7. 迁移到本任务：从”异常检测规则”到”App 指纹分类规则”

本任务的数据（Encrypted_Mobile_Social_Media）与论文场景有三处关键差异，必须显式改造：

维度论文（GEAD）本任务数据
学习范式零正异常检测（只喂正常流量）有监督多分类（10 个 App 全都有标签）
模型输出单一异常分10 维类别概率
标签可靠性正常流量干净含大量背景噪声流（SSDP/MDNS/DNS 等），标签是”当时前台 App”，流本身未必属于该 App

改造方案（本报告采用）：

  1. 保留”流量表示粒度”：流级 NFStream 特征（= CICIDS2017 档），并增加会话级聚合（按 capture_file × src_ip 聚合，对应 README 的 multi-flow aggregation）。
  2. 保留”四类特征依据”：把 92 列按 §2 的四族重新归并，形成可解释的特征视图。
  3. 保留”连续分数”思想：不用分类树，而是对每个 App 训练一个回归树去拟合黑盒模型输出的 P(App)，再做 LC 叶增广细化。
  4. 保留”LC 增广”：在 LC 叶的路径约束子空间内对特征做扰动（本任务无梯度可用时用”分布内扰动 + 边界推挤”），生成模型与原树不一致的样本。
  5. 保留”合并 + 离散化 + 可读规则”：输出形如 IF dst_port=443 AND bwd_bytes_ratio < 0.15 AND bidirectional_mean_ps > 400 THEN YouTube 这样的规则，并把连续阈值离散成 small/large。
  6. 保留”保真度 + 简洁度 + OOD”：用**跨天（Day-5 holdout）**充当 OOD 评估，避免论文 Fig.1 指出的 IID 假保真。
  7. 显式处理 Insight 3 的”标签错误”：先用论文的”特征/标签/模型”三查表定位噪声流（背景流量），再决定是否过滤。

8. 可直接复用的”分类依据 + 方法”清单（本文档交付摘要）

A. 分类依据（判据）

  • A1 体量与包长统计（bytes/packets、ps 的 min/mean/stddev/max、上下行字节比）
  • A2 时间与到达间隔统计（duration、piat 的 min/mean/stddev/max）
  • A3 传输层协议与标志位（protocol、SYN/ACK/PSH/RST/FIN 计数、双向比）
  • A4 服务/端口/主机画像（dst_port、SNI、JA4/JA3 指纹、DPI 应用标签）
  • A5 会话/多流聚合上下文（同一设备同一天的多条流联合判定）

B. 分类方法

  • B1 零正异常检测（重构式 AE/KitNET、预测式 LSTM/DeepLog）+ 阈值
  • B2 有监督多分类（本任务主线）
  • B3 规则蒸馏（GEAD：root tree → LC 识别 → LC 增广 → 子树 → 合并离散化 → 可读规则）
  • B4 保真度评估（Positive Consistency / Negative Credibility，IID+OOD）
  • B5 简洁度控制（预剪枝 M_d/M_s，规则预算）
